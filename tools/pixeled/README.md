# Pixel Editor (hand-cleaning animal frames)

The user's sprite editor, published as its own claude.ai Artifact: https://claude.ai/artifact/EM2pt152SMWcat2DraeLHj (private, separate from the game's preview). It is v1's editor plus a **Park frames** tab that opens every `art/source/<species>/<strip>-N.png` as one strip per animation.

## Files
- `index.html`, `js/pixeled.js`: the editor page and logic, kept here as the source. Page has no doctype/head (the publish adds them), like the game's `index.html`.
- Not in the repo (copied from v1's editor, already in the artifact): `js/data.js`, `js/geometry.js`, `js/sim.js`, `js/landscape.js`, `js/spritepack.js`. Publishing with `files` leaves files you don't list alone, so you never need them locally.
- `js/v2pack.js`: generated by `tools/sprites/pixelpack.py` (not committed).

## Change the editor
Edit `js/pixeled.js` here, then publish with `url` = the editor link, `file_path` = `tools/pixeled/index.html`, `files` = `{"js/pixeled.js": "tools/pixeled/js/pixeled.js", "js/v2pack.js": "<generated pack>"}`. Read the live page first (the publish is refused otherwise).

## Hand-cleaning loop
1. Rebuild the pack when source frames changed: `python3 tools/sprites/pixelpack.py <out>/v2pack.js`, then republish the editor with it.
2. The user opens a strip in **Park frames**, edits, and hits **Send to repo**. The strip lands in the editor's database, collection `pixeled`, doc id = path with `/` as `~` (e.g. `art~source~dimetrodon~rest.png`). The user says when they've sent.
3. Read it with `ArtifactData` (`action: get`, the editor's `url`, `collection: pixeled`, `doc_id`, `out_dir`). Each send replaces the last, so re-read on every "sent again".
4. Write the doc's `png` field (a data URI) to a file and run `python3 tools/sprites/pixelpull.py --b64 <species> <strip> <file>`. It writes the numbered source frames and reports visible pixels changed per frame (colour under transparent pixels doesn't count). Frames the strip builder drops (a repeat of the first or of the previous frame) show as changed but never reach the game: tell the user.
5. `python3 tools/sprites/strips.py <species> <the species' flags>` rebuilds `art/animals/`. Use the species' flags from its `data.js` entry (Dimetrodon: `--shift -4 --anchor-y 48`).
6. `gifs.py` the old (stash `art/animals`) and new strips, send both with SendUserFile, and wait for the user's yes. Then commit, push and republish the game preview.
7. Hand-edited species: never regenerate their `art/source/` with PixelLab without asking.
